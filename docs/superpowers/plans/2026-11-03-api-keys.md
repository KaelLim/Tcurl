# 服務 API 金鑰 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 管理者可發放 `tcurl_sk_` API 金鑰給內部服務；金鑰以負責同仁名義呼叫既有 `/api/urls…` 端點，且只能碰自己建立的短網址。

**Architecture:** DB 新增 `api_keys` 表與一組 service-role-only RPC（驗證、發放、撤銷、更新／轉移、列表），以 trigger 保護 `urls.api_key_id`、讓稽核紀錄帶上金鑰。Worker 在限流之前用中介層辨識金鑰、查白名單決定權限，再把呼叫者放進 `c.var.apiKey`；各路由遇到金鑰時改用 service client，並同時限定 `created_by = ownerId` 與 `api_key_id = keyId`。

**Tech Stack:** Cloudflare Workers + Hono、Supabase（PostgREST / PL/pgSQL）、Vitest、Workers Rate Limiting、Vanilla JS 前端。

**Spec:** `docs/superpowers/specs/2026-11-03-api-keys-design.md`（執行者必讀；本計畫的章節號 §x.y 指 spec）

## Global Constraints

- 金鑰格式：`tcurl_sk_` + 32 bytes 亂數的 base64url（無 `=`）；顯示用前綴 = 金鑰前 15 字元；DB 只存 SHA-256 hex。
- 完整金鑰只出現在 `POST /api/admin/api-keys` 的回應；任何其他回應、記錄、DB 都不得出現。
- 權限值只有 `'read'`、`'write'`；預設兩者。到期選項 90 天／1 年／不過期，預設 1 年。
- 金鑰限流：新 binding `API_KEY_RATE_LIMITER`，namespace `'1004'`，`{ limit: 300, period: 60 }`，鍵為 keyId。
- 錯誤碼：金鑰無效／失效／不允許的端點 → 401 `{ error: 'Unauthorized', message: 'API 金鑰無效或已失效' }`；權限不足 → 403；不屬於該金鑰 → 404。
- 新 RPC 一律 `SECURITY DEFINER`、`SET search_path = ''`、`REVOKE EXECUTE … FROM PUBLIC, anon, authenticated`、`GRANT … TO service_role`（比照 `20261102044647_restrict_rpc_to_service_role.sql`）。
- 「是否為後端（service role）呼叫」在 SQL 內一律用 `auth.role()` 判斷，**不可**用 `current_user`（SECURITY DEFINER 內 `current_user` 是函式擁有者）。
- 不得自行套用 migration 或部署；Task 9 由主流程在使用者同意後執行。不得 commit，除非使用者要求。
- 與 spec 的一處差異（設計者決定）：§6.4 說 `last_used_at` 在背景更新；本計畫改在 `verify_api_key` RPC 內順便更新（每分鐘最多寫一次），省掉每個請求多一次資料庫往返。
- 程式慣例：見 `CLAUDE.md`（`.ts` 副檔名 import、`c.env`、`runInBackground`、Vitest `*_test.ts`、`tests/helpers/test-env.ts` 替身）。

## Review Focus

1. 從後台複製金鑰時夾帶前後空白或換行 → 應照常驗證成功（Task 2 測試 `parseBearer` 去空白）。
2. `Authorization` 只有金鑰沒有 `Bearer `、或 `bearer` 小寫 → 不得 500；小寫 `bearer` 視同 `Bearer`，沒有 scheme 回 401（Task 3）。
3. 管理者發放時選了過去的到期日 → 400，不建立金鑰（Task 6）。
4. 負責同仁 email 大小寫不同或有空白（` Kael1996@Tzuchi.org.tw `）→ 正確找到同一人（Task 1 SQL、Task 6）。
5. 金鑰帶非 UUID 的 `:id`（如 `/api/urls/abc`）→ 404，不是 500（Task 4）。
